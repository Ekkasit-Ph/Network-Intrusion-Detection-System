**ข้อ 1 วัดอะไรบ้าง** — เขียนเป็น `scripts/benchmark.py` ออกผลเป็น `artifacts/benchmark.json`
- throughput: flow/วินาที ที่สกัด + ที่ให้คะแนนได้
- latency: p50/p95/p99 ของการให้คะแนน 1 flow
- หน่วยความจำ: RSS ตอนโหลดโมเดล + ตอนรันจริง
- SHAP: latency ต่อ flow (มีข้อมูลแล้ว 8–28 ms แต่ต้องวัดเป็นระบบ)
- เทียบ CPU กับ GPU

### 🟧 สัปดาห์ 2–4 — ปิดคำถามที่กรรมการถามแน่

| # | งาน | ได้อะไร | แรง |
|---|---|---|---|
| 4 | **เทียบ baseline** — *ข้ามไปก่อนตามที่ตกลง* | ตอบ *"ทำไมต้อง autoencoder"* ด้วยตัวเลข | 3 วัน |
| 2 | ✅ **ประเมิน explainability** | ปิดแทร็กที่สัญญาไว้ · เจอว่า nsamples=100 ใช้ไม่ได้ | เสร็จแล้ว |
| 5 | ✅ **threshold แยกตามโปรโตคอล** | **ทดลองแล้ว ผลเป็นลบ ไม่นำไปใช้** → [protocol-threshold-experiment.md](protocol-threshold-experiment.md) | เสร็จแล้ว |

**ข้อ 4 เทียบกับอะไร** — ทุกตัวฝึกด้วย benign อย่างเดียวเหมือนกัน วัดที่ FPR 5% เท่ากัน
- Isolation Forest (scikit-learn มีอยู่แล้ว ไม่ต้องลงอะไรเพิ่ม)
- One-Class SVM (ต้อง subsample ไม่งั้นช้ามาก)
- PCA reconstruction error ← baseline ที่ตรงแนวคิดที่สุด
- ค่ามัธยฐานเฉย ๆ (sanity check ว่าโมเดลดีกว่าการเดา)

ออกเป็นตารางเดียว: `recall @ FPR 5%`, macro F1, เวลาฝึก, เวลา inference, ขนาดโมเดล
→ ถ้า autoencoder ไม่ชนะ **ก็รายงานตามจริง** นั่นคือผลการทดลองที่ถูกต้อง

**ข้อ 2 ประเมิน SHAP ยังไง** — สามอย่างที่วัดได้จริง
- **Local Accuracy** — `base + Σshap = error` แดชบอร์ดแสดงอยู่แล้ว แค่วัดเป็นสถิติ (ค่าคลาดเคลื่อนสูงสุดจาก N flow)
- **Faithfulness** — ลบ top-k ฟีเจอร์ที่ SHAP บอกว่าสำคัญออก (แทนด้วยค่าเฉลี่ย) แล้วดูว่า error ตกลงจริงไหม เทียบกับลบฟีเจอร์สุ่ม ถ้าตกมากกว่า = คำอธิบายเชื่อถือได้
- **Stability** — flow ที่คล้ายกันควรได้คำอธิบายคล้ายกัน วัดด้วย rank correlation
