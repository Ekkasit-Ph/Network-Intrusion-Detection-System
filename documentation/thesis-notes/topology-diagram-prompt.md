คัดลอกข้อความในกรอบด้านล่างทั้งหมดไปวางใน Claude Design

> **ตัวเลขทุกตัวในนี้ดึงจากเครือข่ายที่รันจริงบน VM เมื่อ 20 ก.ย. 2569** ไม่ได้อ่านจากโค้ด
> — หมายเลขพอร์ต MAC และกฎ OpenFlow ตรวจสอบด้วย `ovs-ofctl dump-flows` แล้ว

## ข้อความ prompt

```
วาดแผนภาพเครือข่ายจำลอง (Network Topology Diagram) สำหรับรายงานโครงงานปริญญาตรี
ภาษาไทย เรื่อง "ระบบตรวจจับการบุกรุกเครือข่ายโดยใช้ออโตเอนโค้ดเดอร์และปัญญาประดิษฐ์
ที่อธิบายได้"

## บริบทการใช้งาน
- เป็นรูปประกอบในเล่มรายงานวิชาการ พิมพ์ลงกระดาษ A4 ขนาดประมาณ 16 x 11 ซม.
- ต้องอ่านออกเมื่อพิมพ์ขาวดำ ห้ามใช้สีเป็นตัวแยกความหมายเพียงอย่างเดียว
  ให้ใช้เส้นทึบ/เส้นประ ความหนาของเส้น และรูปทรงกล่องช่วยแยกด้วย
- ป้ายกำกับใช้ภาษาไทยเป็นหลัก ตามด้วยศัพท์เทคนิคภาษาอังกฤษในวงเล็บ
- สไตล์เรียบ เป็นทางการ ไม่ต้องมีไอคอนตกแต่ง ไม่มีเงา ไม่มีไล่สี
- ให้เข้าชุดกับแผนภาพสถาปัตยกรรมระบบในเล่มเดียวกัน

## หัวใจของแผนภาพที่ต้องสื่อให้ถูก
เครือข่ายนี้มีโฮสต์ 8 เครื่องต่อกับสวิตช์ OpenFlow ตัวเดียว แต่ **โฮสต์เครื่องที่ 8
(nids1) ไม่ได้เป็นผู้ใช้เครือข่าย** มันรับ "สำเนา" ของทราฟฟิกทั้งหมดผ่านพอร์ตสำเนา
(SPAN / mirror port)

**เส้นที่ไปยัง nids1 ต้องวาดต่างจากเส้นอื่นอย่างชัดเจน** — เป็นเส้นประ มีหัวลูกศร
ทางเดียว (จากสวิตช์ไปหา nids1 เท่านั้น) เพราะนี่คือประเด็นเชิงออกแบบที่สำคัญที่สุด
ของรูปนี้: ระบบตรวจจับ **ไม่ได้อยู่บนเส้นทางส่งต่อข้อมูล** จึงไม่สามารถบล็อกทราฟฟิก
ได้แม้จะทำงานผิดพลาด ซึ่งเป็นข้อจำกัดข้อแรกของโครงงาน (ห้าม auto-block เพื่อป้องกัน
การตัดเครือข่ายตัวเองจากผลบวกลวง)

## โครงสร้างที่ต้องวาด

### ชั้นบนสุด: ตัวควบคุม
กล่องเดียว วางกลางด้านบน:
"ตัวควบคุมเครือข่าย (Ryu SDN Controller)"
ป้ายกำกับใต้กล่อง: "OpenFlow :6653  ·  REST API :8080"

เส้นจากกล่องนี้ลงมาที่สวิตช์: เส้นทึบ มีหัวลูกศรสองทาง
ป้ายกำกับบนเส้น: "ติดตั้งกฎ / รายงานสถานะ (OpenFlow 1.3)"

### ชั้นกลาง: สวิตช์
กล่องแนวนอนกว้าง วางกลางภาพ:
"สวิตช์ OpenFlow  s1"
ป้ายกำกับเล็กในกล่อง: "Open vSwitch  ·  8 พอร์ต"

### ชั้นล่าง: โฮสต์ 8 เครื่อง แบ่ง 4 กลุ่มตามซับเน็ต
วาดเป็นกรอบเส้นประครอบแต่ละกลุ่ม พร้อมป้ายชื่อซับเน็ตบนกรอบ
เรียงจากซ้ายไปขวาตามลำดับนี้

กลุ่ม 1 — "เครือข่ายอุปกรณ์ IoT  10.0.1.0/24"  (4 กล่อง)
  iot1  10.0.1.11   (พอร์ต 1)
  iot2  10.0.1.12   (พอร์ต 2)
  iot3  10.0.1.13   (พอร์ต 3)
  iot4  10.0.1.14   (พอร์ต 4)
  หมายเหตุใต้กรอบ: "อุปกรณ์ปลายทาง สร้างทราฟฟิกปกติ"

กลุ่ม 2 — "เครือข่ายเซิร์ฟเวอร์  10.0.2.0/24"  (2 กล่อง)
  srv1  10.0.2.11   (พอร์ต 5)
  srv2  10.0.2.12   (พอร์ต 6)
  หมายเหตุใต้กรอบ: "ให้บริการ HTTP พอร์ต 80 และ 8080"

กลุ่ม 3 — "เครือข่ายผู้โจมตี  10.0.3.0/24"  (1 กล่อง)
  atk1  10.0.3.11   (พอร์ต 7)
  หมายเหตุใต้กรอบ: "รันสคริปต์โจมตี: สแกนพอร์ต / DDoS / เดารหัสผ่าน"

กลุ่ม 4 — "เครือข่ายเฝ้าระวัง  10.0.4.0/24"  (1 กล่อง — วาดให้เด่นกว่ากลุ่มอื่น
           เช่น เส้นขอบหนากว่า หรือพื้นหลังอ่อน)
  nids1  10.0.4.11  (พอร์ต 8)
  ข้อความในกล่อง (ขนาดเล็กกว่าชื่อโฮสต์):
    "โมดูล 1 สกัดโฟลว์ (NFStream)"
    "โมดูล 2 เตรียมข้อมูล"
    "โมดูล 3 ตรวจจับ (Autoencoder)"
  หมายเหตุใต้กรอบ: "อยู่คนละซับเน็ต ทราฟฟิกของตัวเองจึงไม่ปนในข้อมูลที่เก็บ"

### เส้นเชื่อม — ต้องแยกสองแบบให้ชัด

แบบที่ 1 (โฮสต์ 1–7): เส้นทึบ ไม่มีหัวลูกศร เชื่อมแต่ละโฮสต์กับสวิตช์
  ป้ายกำกับรวมครั้งเดียวพอ: "100 Mbps · หน่วงเวลา 2 ms"

แบบที่ 2 (nids1 เท่านั้น): **เส้นประ หนากว่าเส้นอื่น มีหัวลูกศรทางเดียว
  จากสวิตช์ → nids1**
  ป้ายกำกับบนเส้น: "พอร์ตสำเนาทราฟฟิก (SPAN / Mirror Port)"
  ป้ายกำกับรอง ตัวเล็กกว่า: "สำเนาทุกพอร์ต ทั้งขาเข้าและขาออก"

### กล่องคำอธิบายมุมขวาล่าง (Legend / หมายเหตุ)
กรอบเส้นทึบบาง ใส่ข้อความ 2 บรรทัด:
"─── เส้นทางส่งต่อข้อมูลจริง (สองทิศทาง)"
"- - -▶ สำเนาทราฟฟิกทางเดียว ระบบตรวจจับไม่สามารถส่งข้อมูลกลับเข้าเครือข่ายได้"

### กล่องกฎไฟร์วอลล์ — วางชิดสวิตช์ด้านขวา
กรอบเล็ก ๆ ต่อออกมาจากสวิตช์ ชื่อกรอบ "นโยบายไฟร์วอลล์ที่ติดตั้งบนสวิตช์ (9 กฎ)"
แสดงเฉพาะกฎที่ปิดกั้น 3 ข้อ:
  "ลำดับ 300  TCP พอร์ต 445 จาก 10.0.1.0/24  →  ปิดกั้น"
  "ลำดับ 300  TCP พอร์ต 23 (Telnet)          →  ปิดกั้น"
  "ลำดับ 300  TCP พอร์ต 3389 (RDP)           →  ปิดกั้น"
บรรทัดสุดท้ายตัวเอียง: "และกฎอนุญาตอีก 6 ข้อ"

## ข้อกำหนดเพิ่มเติม
- อย่าวาดลูกศรทิศทางของทราฟฟิกระหว่างโฮสต์ (เช่น atk1 ยิงไป srv1)
  รูปนี้แสดง "โครงสร้าง" ไม่ใช่ "เหตุการณ์"
- หมายเลขพอร์ตของสวิตช์ (พอร์ต 1–8) ต้องแสดงตรงจุดที่เส้นบรรจบกับกล่องสวิตช์
- ชื่อโฮสต์ใช้ตัวพิมพ์เล็กทั้งหมดตามจริง (iot1 ไม่ใช่ IoT1)
- ไม่ต้องใส่ MAC address ในรูป รกเกินไปสำหรับขนาดที่พิมพ์
- คำบรรยายภาพ (caption) ให้เขียนแยกใต้รูปว่า:
  "รูปภาพที่ X โครงสร้างเครือข่ายจำลองสำหรับการทดสอบการทำงานร่วมกันของระบบ"
```
